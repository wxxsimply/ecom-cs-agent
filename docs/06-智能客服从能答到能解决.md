## 1. 本轮要解决什么

用户提出三条需求：

1. **不要机械回复“无法回答”**：要先理解用户意图，再给出对应的回答、澄清或下一步。
2. **AI 客服的目标是替代人工**：非紧急情况不应动辄呼叫人工；要尽量自助解决。
3. **做市场调研**：看京东、淘宝等平台智能客服怎么做、有什么痛点，列出 50 个本项目可学习或可解决的问题，并给出几个合理改动。

本文只做需求、调研、方案和审查，不修改代码。

## 2. 需求澄清

### 2.1 把“机械回复”定义清楚

以下都算机械回复，必须禁止：

- 用户还没说完，就直接回“抱歉，我无法回答”；
- 不区分“知识库没有”“能力不支持”“政策不允许”“需要更多信息”，统一用同一个模板；
- 不结合上文的订单、商品、物流、退款上下文；
- 不给出任何下一步，只把用户推给人工；
- 同一个问题重复两次相同答案，不换策略；
- 用户问 A，客服答 B，或只答“请描述清楚”；
- 把“转人工”当作默认兜底，而不是例外。

**目标回答形态**：

```text
我理解你想解决的是：<复述意图>
目前我能确认的是：<已查到的信息/规则>
还需要你补充：<一个问题，可选>
我能为你做的是：<下一步/操作/选项>
```

### 2.2 “非紧急不呼叫人工”的边界

“人工”分两种，不能混：

| 类型 | 说明 | 是否允许 |
| --- | --- | --- |
| 实时人工坐席 | 立即转真人，排队 | 仅紧急/高风险 |
| 异步人工工单 | 记录问题，稍后人工跟进 | 非紧急可用，但必须先给出自助方案 |

**允许实时人工的紧急情况**（白名单）：

- 人身安全、诈骗、盗刷、账号被盗、法律风险；
- 高金额/不可逆操作超出 AI 权限，且用户拒绝自助方案；
- 物流显示已签收但用户明确表示未收到，且涉及高价值/生鲜/时效；
- 用户连续两轮明确表达强烈不满，且 AI 已给出可执行方案仍无法推进；
- 平台规则要求必须人工处理的投诉/监管场景。

**非紧急情况**：

- 普通退款、退货、换货、发票、会员、积分、运费、商品咨询、物流查询；
- 用户说“转人工”但没有紧急事由；
- 用户情绪不好但问题本身可解决；
- 知识库没有答案但可以澄清/给替代方案。

处理顺序：

```text
理解意图 → 查证据/工具 → 能答则答 → 不完整则澄清
→ 不能直接办则给替代方案/工单 → 只有紧急才实时人工
```

### 2.3 本轮非目标

- 不做真正的“全自主退款打款”；高风险动作仍需确认/审核。
- 不接京东/淘宝真实 API；调研只做设计参考。
- 不做多模态图片识别、语音、数字人；列为 P1。
- 不把“所有问题都答”作为目标；安全、法律、隐私边界仍然保留。
- 本轮不改代码。

## 4. 市场调研：京东、淘宝等平台怎么做

> 以下数据来自公开报道/厂商材料，属于**厂商自述或媒体转述**，不能直接当作本项目承诺；用于设计参考。来源见第 10 节。

### 4.1 京东：京小智 5.0

公开报道显示，京小智 5.0 的方向是“Agent 原生 + 全链路”：

- 从“成本优化工具”转向“品牌增长引擎”；
- JoyAI 大模型 + 多 Agent 协作；
- 覆盖客服、导购、跟单、分析、质检；
- 20+ 高频场景（商品咨询、国补、商品比较、活动、尺码等）；
- 打通国补、物流、活动、价保等十余个平台业务系统，Agent 自行规划调用工具；
- 支持多模态图文理解、上下文/长期记忆；
- 厂商称内测店铺转人工率降低 28%+、满意度提升 15%+、售前转化提升 37%+；
- 另有“电商客服思维链/可解释”方向，强调让用户理解 AI 的判断依据。

**可学习点**：不是“问答机器人”，而是“能查、能办、能解释、能主动跟单”的 Agent；工具编排和业务系统打通是降人工的关键。

### 4.2 淘宝：店小蜜 5.0

公开报道显示，店小蜜 5.0 的方向是“Agent + 主动服务”：

- 用户进线时动态生成画像、预判意图；
- 售前从单轮问答升级为“多轮探需”，会追问、会表达情绪；
- 能理解文字和图片，结合商品卖点、服务保障、活动优惠给方案；
- 售后以“解决问题”为目标，集成平台能力和商家工单，厂商称 60%+ 售后人工工作可由机器人自动化；
- 与商家工单/仓储/物流协同，自动流转关键信息；
- 厂商称转人工率降低 20%+、成交转化提升 35%+；
- 有店铺反馈“Agent 解决 75% 简单问题，人工专注 20% 复杂问题”。

**可学习点**：售前“探需 + 推荐理由”，售后“工单流转 + 主动跟进”，以及“简单问题机器解决、复杂问题给人”的分层，而不是一刀切转人工。

### 4.3 京东“猜你想问”：模糊问法的处理

第三方服务商文档描述了京东场景的“相似问题 + 关联问题”：

- 用户问法模糊时，推送相似问题卡片，引导点选；
- 回答完一个问题后，推送高概率关联问题；
- 用算法补充相似/关联问题，降低商家配置成本；
- 解决“问得太模糊”“多轮问法多样”“配置不足”三个问题。

**可学习点**：模糊不是拒答理由；先给候选意图让用户点选，再回答。对本项目可直接落地为“澄清候选卡片”。

### 4.4 市场痛点：为什么用户反感 AI 客服

公开报道和消费者反馈中，反复出现这些痛点：

- **重复机械回复**：用户换了说法，AI 仍回同一句；
- **上下文丢失**：每次都要重新描述订单/问题；
- **转人工迷宫**：多次点击、反复选项，仍接不到真人；
- **强制挡流**：企业把 AI 当“成本挡板”，不是解决问题；
- **答非所问**：只会关键词匹配，不理解真实意图；
- **复杂问题无解**：政策例外、赔付、投诉、跨部门问题被踢皮球；
- **情绪激化**：用户着急时，AI 仍冷冰冰模板；
- **不透明**：用户不知道 AI 能做什么、为什么这样答；
- **无障碍不足**：老人、视障、非标准表达用户被排除；
- **隐私担忧**：订单、地址、电话被过度收集/展示。

这些痛点正好对应本轮三条需求：**先理解、尽量解决、非紧急不转人工**。

## 6. 方案设计：从“拒答”到“解决”

### 6.1 回答阶梯（Answer Ladder）

每个用户问题按以下顺序处理，禁止直接跳到“无法回答”：

```text
L0 安全/紧急判断
  ↓ 非紧急
L1 意图识别：业务/一般/模糊/操作/情绪
  ↓
L2 证据检索：知识库/订单/物流/退款/价格工具
  ↓
L3 能直接答 → 回答 + 引用/数据 + 下一步
   信息不足 → 给部分答案 + 只问一个关键问题
   能力不足 → 说明边界 + 给最接近的替代方案
   政策不允许 → 解释规则 + 给合规路径
  ↓
L4 仍无法推进 → 异步工单（非紧急）/ 实时人工（紧急）
```

**硬规则**：

- 不允许第一句就是“抱歉，无法处理”；
- 至少包含一个“已确认的信息”或“可执行的下一步”；
- 连续两轮同一意图无进展，必须换策略（澄清/举例/工单），不能重复同一句；
- 回答不确定时用条件句，不假装确定。

### 6.2 意图体系扩展

当前 10 类保留，新增/细化：

| 意图 | 用途 | 出口 |
| --- | --- | --- |
| `general_qa` | 与商城相关的一般知识/使用建议 | 回答（标注非平台政策） |
| `product_compare` | 商品对比/选购 | 对比工具 + 回答 |
| `order_change` | 改地址/改规格/取消 | 条件判断 + 自助/工单 |
| `invoice_request` | 发票 | 表单/工单 |
| `compensation_request` | 补偿/优惠 | 规则 + 审核 |
| `human_request` | 用户明确要人工 | 先自助方案，再工单/紧急实时 |
| `emergency` | 安全/诈骗/高价值异常 | 实时人工白名单 |
| `out_of_scope` | 真正无关/无能力 | 理解 + 边界 + 替代方案 |

`out_of_scope` 不再是“统一拒答”，而是“边界回答”：

```text
我理解你想问的是 <复述>。
这件事我目前不能直接处理，因为 <能力/权限/实时数据限制>。
不过我可以帮你：
1) <最接近的可执行动作>
2. <相关业务问题>
3. <记录工单/转人工>
你更想先做哪一个？
```

### 6.3 人工策略：默认自助，例外人工

| 场景 | 策略 |
| --- | --- |
| 普通咨询/退款/物流/发票 | AI 自助完成或给明确下一步 |
| 用户说“转人工”但无紧急事由 | 先给自助方案；用户坚持则创建异步工单，不立刻占实时坐席 |
| 投诉/情绪 | 共情 + 复述 + 补救方案；不自动转人工 |
| 复杂例外/权限外 | 建工单 + 预计响应时间；可追踪 |
| 紧急（安全/诈骗/高价值未收到） | 实时人工白名单 |
| AI 连续两轮无进展 | 升级工单；紧急才实时 |

**指标**：不要只考核“转人工率”，同时看：

- 自助解决率；
- 一次解决率；
- 重复进线率（7 天同问题）；
- 用户满意度/点踩率；
- 人工工单率（非紧急）；
- 机械回复率（人工抽检）；
- 幻觉/无依据回答率。

### 6.4 回答质量与透明

- 政策/金额/时效必须有知识或工具依据；无依据时标注“我需要确认”。
- 不展示原始思维链；展示“依据 + 关键判断 + 下一步”（可解释，不是暴露推理）。
- 金额、时效、赔付用工具结果，不让模型口算。
- 回答中明确“我能做什么/不能做什么”，避免用户反复试。
- 首轮/首次人工时明确 AI 身份。

### 6.5 主动服务

- 物流异常/延迟/派送/签收主动通知；
- 退款进度主动更新；
- 大促/缺货/补货提醒；
- 但必须可关闭，不能变成骚扰。

## 7. 三个合理的改动（建议按顺序）

### 改动 A：Answer-first 兜底（推荐先做，P0，约 2–3 天）

**内容**：

- 重写 `out_of_scope`：理解复述 + 边界 + 3 个替代动作；
- 新增 `general_qa`/`needs_clarify` 路由；
- 增加“连续两轮同意图无进展 → 换策略”；
- 非紧急不直接 `handoff`；投诉先共情 + 方案；
- 评测集增加 50 条“机械回复/答非所问”样例。

**收益**：直接解决用户第 1 条需求；改动集中在 prompt/路由/模板，风险低。

### 改动 B：自主解决率提升（P0/P1，约 3–5 天）

**内容**：

- 意图扩展到商品对比、发票、改地址、补偿、紧急；
- 增加“澄清候选卡片”（参考京东猜你想问）；
- 退款/物流/价格工具结果结构化，回答带 breakdown；
- 连续失败转异步工单，而不是实时人工；
- 增加“解决率/重复进线率/机械回复率”指标。

**收益**：直接服务“替代人工”目标；需要工具和评测投入。

### 改动 C：人工协作与主动服务（P1，约 1–2 周）

**内容**：

- 实时人工白名单 + 异步工单队列 + 预计响应时间；
- 人工处理结果回写知识/评测；
- 物流异常/退款进度主动通知；
- 多模态图片/截图（P1）；
- A/B 测试回答策略和转人工阈值。

**收益**：把“人工”从默认兜底变成例外；需要运营和工程共同投入。

**决策**：已选择并实施 **方案 A**（Answer-first 兜底），50 条评测见 CONTEXT v2.0 §11；B/C 暂缓。

**建议**：先做 A，紧接着做 B 的核心 3 项（意图扩展、澄清卡片、指标），C 放下一阶段。

## 11. 结论

- 用户的三条需求方向一致：**先理解、尽量解决、人工只做例外**。
- 市场头部平台已经从“关键词问答”走向“Agent + 工具 + 主动服务 + 工单协同”，但用户仍普遍反感“机械挡流、重复回复、转人工迷宫”。
- 本项目最小、最高收益的改动是 **A：Answer-first 兜底 + 意图/澄清/人工策略**；随后做 **B 的核心 3 项**；C 作为下一阶段。
- 50 项不是一次性全做，按 P0/P1/P2 分批，用解决率、重复进线率、机械回复率、CSAT 验证，而不是只看转人工率。
