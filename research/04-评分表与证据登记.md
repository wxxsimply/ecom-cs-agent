# 评分表与证据登记

> 目的：把“商家说还行”变成可复核的数字；把“我觉得”变成带来源的证据。

## 1. 单条工单评分（5 分制）

| 分 | 含义 | 判定 |
| --- | --- | --- |
| 5 | 可直接采纳 | 动作、金额、依据都对，客服不用改 |
| 4 | 小改后采纳 | 动作对，措辞/补充信息需微调 |
| 3 | 大改后采纳 | 动作或金额需改，但方向可用 |
| 2 | 不可用 | 方向不对，但能看出意图 |
| 1 | 错误 | 含金额/资格/政策引用错误，**单独计数** |

**金额错误单列**：错退、多退、少退、错判资格——出现 1 条就算失败，不参与平均分。

## 2. 每条记录什么

| 字段 | 说明 |
| --- | --- |
| `ticket_id` | 与数据集/私有工单对应 |
| `predicted_action` / `expected_action` | 动作是否一致 |
| `predicted_amount` / `expected_amount` | 金额是否完全一致 |
| `predicted_human` / `expected_human` | 该转人工有没有转 |
| `policy_ref_hit` | 引用是否命中正确条款 |
| `score` | 1–5 |
| `seconds_saved` | 与人工基线相比（自报或计时） |
| `extra_system` | 是否还要开别的系统 |
| `comment` | 商家原话（脱敏） |

## 3. 评分表（CSV）

```csv
ticket_id,predicted_action,expected_action,predicted_amount,expected_amount,predicted_human,expected_human,policy_ref_hit,score,seconds_saved,extra_system,comment
R-001,refund_apply,refund_apply,239,239,false,false,true,5,420,false,"直接退，别再问"
```

## 4. 汇总指标

| 指标 | 公式 | 用途 |
| --- | --- | --- |
| 可采纳率 | `(score>=4 的条数) / N` | 主指标 |
| 金额错误数 | `predicted_amount != expected_amount` 的条数 | **硬门槛，必须 0** |
| 人工标记准确率 | `predicted_human == expected_human` 的比例 | 漏转人工比多转更危险 |
| 政策引用命中率 | `policy_ref_hit` 为真的比例 | 证据可追溯 |
| 平均节省时间 | `sum(seconds_saved)/N` | 价值 |
| 需开额外系统比例 | `extra_system` 为真的比例 | 跨系统价值 |

> 样本 <40 条时，只报“方向性结论”，不报百分比置信区间；50% 和 70% 在 10 条样本里没有统计意义。

## 5. 证据表

```csv
id,假设,来源类型,来源,原文或原话,可信度,影响决策,日期
E001,H1,访谈,受访者A（客服主管/自营商城/鞋类）,"最近一单退款开了3个系统，18分钟",B,是否做判责层,2026-11-05
E002,H2,实测,数据集 T-036,"699 元质量问题，规则要求转人工",A,金额阈值,2026-11-06
E003,H3,招聘JD,淘工作客服主管,"监控退款率/纠纷率/满意度",B,买家KPI,2026-11-03
```

可信度：**A** 官方文档/实测；**B** 一手访谈/截图/JD；**C** 媒体/厂商宣称；**U** 未核实。

## 6. 防偏差

- 不告诉商家“这是 AI 生成的”，只说“处理建议”；
- 同一商家的工单打乱顺序；同一单至少 2 人评（主管 + 客服）；
- 区分“礼貌分”（说好）与“行为分”（愿意给下一批工单/试用）；
- 记录“拒绝理由”，不要只记录“拒绝”；
- 商家说“可以”但不再回复，按“未采纳”算，不按“有意向”算。

## 7. 每次访谈后的 10 分钟

1. 更新证据表（至少 2 条）；
2. 更新评分表（如果有工单）；
3. 写 1 句“这次推翻了我什么”；
4. 如果连续 3 位都推翻同一个假设，改设计，不要改话术。
