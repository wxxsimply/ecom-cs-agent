# 材料请求与脱敏

> 原则：**先给脱敏规则，再要材料；只要结构，不要身份**。
> 真实工单只进本地 `data/eval/private/`（已 gitignore），不提交、不外传、90 天后删除。

## 1. 要什么（按优先级）

| 优先级 | 材料 | 用途 | 替代方案 |
| --- | --- | --- | --- |
| P0 | 5–10 张脱敏工单（退款/退货/换货/物流异常各 2–3 张） | 校准意图、动作、金额 | 口述 3 单 + 你记笔记 |
| P0 | 售后政策文档（退换/运费/时效/例外） | 政策引用与判责 | 截图/口述要点 |
| P1 | 退款审批规则（谁批、多少金额、例外） | 人工阈值 | 口述 |
| P1 | 一次 30 分钟后台演示（可录屏/只看） | 了解系统与字段 | 截图打码 |
| P2 | 近 3 个月退款率/纠纷率/人效 | 量化痛点 | 只给区间 |

## 2. 怎么开口（发一次）

> 为了不涉及客户信息，我只需要**脱敏后的工单结构**：把姓名/电话/地址/订单号替换掉，日期整体平移，金额可保留或改成区间。你可以先发 1 张给我看格式，觉得可以再发剩下的；不方便的部分跳过。

## 3. 脱敏规则

### 3.1 直接标识（必须删/替换）

| 字段 | 处理 |
| --- | --- |
| 姓名、昵称、微信名 | 替换为“客户 A/B/C” |
| 手机号、座机 | `138****0000` 或删除 |
| 收货地址 | 只保留“省/市”，删街道门牌 |
| 身份证、银行卡、支付账号 | **不要收集**；遇到即删 |
| 订单号、物流单号 | 哈希后 8 位，或替换为 `ORD-001` / `TRK-001` |
| 客服工号、店铺名、公司名 | 替换为“客服 1”“店铺 A” |
| 聊天账号、IMEI、设备号 | 删除 |

### 3.2 准标识（泛化）

| 字段 | 处理 |
| --- | --- |
| 日期 | 整体平移 ±N 天（保持相对间隔），只留“签收后第几天” |
| 城市 | 保留省/市，删除区县与小区 |
| 商品 | 保留品类（鞋/裙/耳机），删除品牌/型号（除非与规则相关） |
| 金额 | 保留精确值用于金额核对；对外展示用区间（如 200–300 元） |
| 图片 | 打码订单号/头像/地址；人脸不收集 |

### 3.3 保留什么

- 客户原话（去掉身份信息）；
- 订单状态、签收天数、金额、品类、可退性；
- 客服处理步骤（查了哪个系统、看了哪条政策、谁批准）；
- 结果（退/换/拒/转人工）与耗时。

## 4. 知情同意（短版，发给对方确认）

> 我仅将材料用于个人求职作品的能力评估；会删除姓名、电话、地址、订单号等身份信息；不外传、不用于训练、不上传公网；作品集只展示聚合指标和脱敏片段；你随时可以要求我删除。

## 5. 存储与保留

- 目录：`data/eval/private/`（`.gitignore` 已排除）。
- 命名：`YYYYMMDD-商家编号-工单编号.json`，不要用真实店名。
- 保留：90 天；到期删除，并在 `research/04-评分表与证据登记.md` 记一条“已删除”。
- 备份：不放到网盘/聊天记录；如需备份，用本地加密压缩包。

## 6. 真实工单记录模板（CSV）

```csv
ticket_id,channel,message,order_status,delivered_days,paid,goods,shipping,category,returnable,policy_ref,expected_action,expected_amount,requires_human,merchant_score,merchant_comment
R-001,web,"鞋开胶了，能退吗",delivered,6,239,233,6,shoes,true,returns.md#2,refund_apply,239,false,5,"直接退，别再问"
```

> `expected_*` 先由你按规则填，再让商家评；不要让商家替你填“标准答案”，否则测的是他的表达而不是你的系统。

## 7. 不要收集

- 身份证、银行卡、支付密码、验证码；
- 客户完整聊天记录（除非逐条脱敏）；
- 商家后台账号/密码；
- 未打码的订单截图；
- 任何“只给内部看”的经营数据（除非对方明确同意且你能保管）。

## 8. 对方拒绝给材料时

1. 退一步：只做口述访谈，你记流程；
2. 再退一步：用公开规则 + 合成工单做演示，明确标注“合成”；
3. 不要纠缠；把拒绝原因记进证据表（“数据不可得”本身就是结论）。
