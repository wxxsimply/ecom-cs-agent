# 作品集叙事与演示

> 定位：不是“我做了个创业项目”，而是“我能把一个模糊的客服场景，收敛成可控、可评测、可讲清楚的系统”。

## 1. 作品集结构（6 页就够）

1. **问题**：电商售后不是“答问题”，是“查证—判责—执行—留痕”；错误成本是钱。
2. **约束**：单商家自营商城、无真实 OMS、P0 只能本地演示、模型成本有限。
3. **方案**：Workflow 管确定的事（金额/资格/审批），Agent 管判断；证据闸门；退款子流程；人机边界。
4. **验证**：200 条脱敏工单数据集 + 3–5 位从业者访谈 + 真实模型对比（mock vs 真实）。
5. **失败与修正**：至少讲 2 个被推翻的设计（例如“自动退款”改为“判责+人工确认”；“通用问答”改为“售后执行”）。
6. **下一步**：接一个 ERP 售后 API、补 20 条真实工单、把金额错误率压到 0。

## 2. 5 分钟演示脚本

| 时间 | 画面 | 台词 |
| --- | --- | --- |
| 0:00 | 对话页 | “这是自营商城的客服入口，我用一笔真实结构的工单走一遍。” |
| 0:30 | 输入“耳机有杂音，想退” | “它先识别意图和订单，再查政策，不直接答。” |
| 1:30 | 展示订单/物流/条款引用 | “每个结论都有来源；金额按规则算，不让模型自由发挥。” |
| 2:30 | 699 元显示器场景 | “超过 500 元，自动转人工——这是故意的，不是能力不足。” |
| 3:30 | 拒答/范围外 | “不知道就说不知道，给可执行的下一步。” |
| 4:30 | 数据集与指标 | “200 条工单，150/50 切分；金额错误单独计数，错一单就算失败。” |
| 5:00 | 收尾 | “下一步接 ERP 售后接口，先验证判责，不急着做执行。” |

## 3. 十个必问问题（提前准备）

| 问题 | 回答要点 |
| --- | --- |
| 这和店小蜜/七鱼有什么区别？ | 它们强在平台内/全渠道；我做的是自营商城 + 自有 ERP 的判责与证据层，执行调用 ERP。 |
| 你的数据哪来的？ | 合成 200 条（标注 synthetic）+ 3–5 位从业者访谈校准；真实工单只本地脱敏，不提交。 |
| 模型效果怎么样？ | 给出真实模型在 dev/holdout 的意图/动作/金额指标；mock 结果不作为效果。 |
| 为什么不用多 Agent？ | 退款金额/资格是确定性的，多 Agent 增加不确定性；复杂判断才用 Agent。 |
| 金额错了怎么办？ | 规则引擎 + 500 元人工线 + 确认令牌；金额错误单列，错一单即失败。 |
| 怎么防 Prompt 注入？ | 工具白名单、参数校验、证据闸门、拒答；不把用户文本当指令。 |
| 为什么不做自动打款？ | 资金操作风险高；P0 只创建申请，人工确认。 |
| 怎么评测？ | 意图/动作/金额/人工标记/引用命中；150/50 切分；holdout 只跑一次。 |
| 你最大的失败是什么？ | 先做了通用问答，后来发现竞品已覆盖；改成“判责+执行编排”，并砍掉售前。 |
| 如果给你两周，你做什么？ | 接聚水潭售后 API，拿 20 张真实工单，把金额错误压到 0，再做一次商家复核。 |

## 4. 指标表（放简历/作品集首页）

| 指标 | 数值 | 口径 |
| --- | --- | --- |
| 工单数据集 | 200 条（150 dev / 50 holdout） | 合成 + 规则校验 |
| 意图覆盖 | 13/14 类 | 缺 `human_handoff`（系统动作） |
| 退款边界 | 21 条，含 7 类边界 | 未支付/已取消/已退款/超期/定制/高金额/已发货 |
| 金额错误 | 0（规则层） | 数据集校验 + 单测 |
| 从业者访谈 | 3–5 位 | 匿名 |
| 真实模型引用准确 | 待填 | 跑完 S1 再写 |

> 没有跑真实模型之前，不要写“准确率 90%”；写“规则层金额错误 0，模型效果待测”。

## 5. 不能说的话

- ❌ “已有商家在用”——没有就是没有。
- ❌ “自动退款”——P0 只创建申请。
- ❌ “准确率 95%”——没有 holdout 结果就不要写。
- ❌ “替代人工”——说“减少查证/判责时间，关键动作人工确认”。
- ❌ “接了真实 OMS”——没接就说“Adapter + 样例数据”。
